# F538 — native VC7.1 C++ switch lowering for two complete giant bosses

**Research milestone, not a giant-boss CODE match or a source-ownership claim.**
This work is based on the *complete* original Japanese TH075 1.11 Reimu
(`0045DD70`, **60,999 native CODE bytes**) and CharacterMove (`004AC040`,
**82,796 native CODE bytes**) fighter functions, with original PE SHA256
`bd441e99075436e8dcad26f86ffcf5e6aac4f58b0ed3ee7442e4cb39d8e22c98`.
Their complete original function identities and contiguous post-RET DATA are
checked before each attempt. All original full function code bodies remain
unmatched. No original bytes or assembler directives are transplanted into
source code.

## A single real C++ switch explains the original multi-table architecture

The verified F537 [per-action native dispatch inventory](FIGHTER_ACTION_CASE_RESOLUTION.md)
shows that Reimu has 138 distinct indexed nondefault actions and five
singleton equality actions; CharacterMove has 146 distinct indexed nondefault
actions and five singleton equality actions. The 405/397 indexed inputs
that physically reach native default are **not** added as spurious C++ cases.

Generate **one** ordinary `switch (I16(0x60))` with exactly those native
explicit-case IDs and unique placeholder stores, after a natural
short-circuit guard involving receiver fields `+0x82`, `+0x2E8`, and
`owner +0x3BA`. This demonstrates a viable source/compiler origin of the
original native switch topology rather than claiming to recover the unknown
case implementations. These explicit cases are *deduced from* physical
original tables; their enumeration is not an independent proof of original
source text. Probe case bodies merely write distinct integer test values.

Pin the actual MSVC 7.1 `/Od /Ob0 /Gy /GR- /GX- /GS /Zi` profile and rebuild
*only these two small probe translation units*, not the two full fighters,
using `scripts/compile-probe.sh`. The result is:

| Observed complete-original switch property | 60,999-byte Reimu | 82,796-byte CharacterMove |
| --- | ---: | ---: |
| Natural C++ explicit `case` labels | 143 (138 indexed + 5 singleton) | 151 (146 indexed + 5 singleton) |
| Original switch code region | `0045DDA4..0045DEE8` | `004AC074..004AC1B8` |
| Original instruction grammar reproduced by compiled C++ | **66 / 66** | **66 / 66** |
| Original switch-region instruction lengths and total extent | **325 bytes** | **325 bytes** |
| Original indexed switch groups generated by the *single* C++ switch | **6 / 6** | **6 / 6** |
| Compiler COFF physical DWORD switch references | **142 / 142** | **151 / 151** |
| Original sparse byte-index data reproduced **byte-for-byte** | **522 / 522** | **522 / 522** |
| Full after-RET native DATA *layout* and case-target equivalence partition | **1,090 bytes** | **1,126 bytes** |

All **four** sparse maps per boss match the original *entire* physical byte
sequences (not just length or frequency), including the exact original
49-byte and 68-byte input partitions and two fighter-specific long maps.
The **full 142/151 DWORD target topology** also agrees after original/codegen
case-target addresses are normalized: every slot that originally led to
a native shared default leads to the generated C++ default, and every
repeated vs independent label relationship agrees for all physical DWORD
slots, even across separate indexed tables. These generated objects have
actual `DIR32` COFF relocations for every DWORD slot, not manufactured
address bytes. The 66 aligned dispatch x86 instructions preserve all native
instruction sizes, register choices, immediate threshold values, short/near
branch shapes, internal branch offsets, source expression order and exact
selection of six dense/sparse switch groups. Stack-local offsets, relocated
DWORD addresses, external branch targets and entire action *bodies* do **not**
match and are deliberately normalized **only for this research comparison**.

The important difference from initial separate-guard/extra-local probes is
that **one combined C++ short-circuit condition** and a **direct switch
operand**, rather than an unnecessary named `int action` copy, naturally
recover the original prefix's `JNE`/`JE` ordering and register selection.
The earlier separate-guard versions also generated equal sparse data, but
introduced an extra native stack copy and did not reproduce the complete
same-size 66-instruction switch prefix. The natural C++ local choice is
supported by original physical code and cold compiler output; no synthetic
array/padding or instruction assembly was necessary.

## Reproduce the native-source shape witness

```bash
scripts/repo-python scripts/verify-target.py
scripts/repo-python scripts/report-fighter-action-handlers.py --boss 0x0045DD70
scripts/repo-python scripts/report-fighter-action-handlers.py --boss 0x004AC040
scripts/repo-python scripts/verify-fighter-natural-switch-probes.py
# Or compile/verify *only* one prototype:
scripts/repo-python scripts/verify-fighter-natural-switch-probes.py --boss Reimu
```

The new source verifier regenerates two **ignored** C++ probes under
`.analysis/f538-natural-fighter-switch-source/`, uses the existing pinned
compiler, reads the actual generated COFF symbol, relocation and after-RET
bytes, and checks *the original complete PE CODE and physical DATA again*
from scratch. It rejects missing/extra table slots, a wrong native action
threshold, incorrect registers, any different 325-byte dispatch grammar,
wrong sparse bytes, inconsistent default fallbacks, or a different dense
case-target equivalence partition. Its output records actual verified
compiler/test artifacts, not a fabricated exact comparison.

## What remains to reconstruct in the actual giant functions

This establishes **source-level C++ feasibility for the entire switch
*dispatch***, not the entire giant function. The natural probe intentionally
has dummy case bodies, a small frame, different local EBP displacements,
placeholder global stores and relocated case addresses. The native Reimu
and CharacterMove body logic contains many additional calls, real
fighter-specific actor/animation/movement state mutations, exception
handling and x87 operations. Their actual large source classes and case
bodies must still be reconstructed *within the full original extent* and
passed through **complete CODE plus physical relocation exactness**, rather
than checking 325-byte subsets, table data or similar-looking machine code.
There is **zero new accepted giant CODE**, no all-unit cold replay and no
external Oracle exactness receipt from F538.
