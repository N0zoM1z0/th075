## F732 real newly recovered codegen: 1FA stack width and 1FE/1FF predicate

* Native `1FA` ordinal 16 `MOV [EBP−0x110],EAX` and ordinal 17
  `FILD [EBP−0x110]` are both **6-byte actual original x86
  instructions**. Earlier F666's old, less-complete C++ parent
  generated shorter 3-byte EBP locals and a **281-byte whole case**;
  inserting genuine 1F4–1F8 game source ahead of `1FA` gives the
  compiler a real deeper used stack lifetime, now **both 6-byte
  instructions** and authentic **287-byte** whole-case geometry.
  The actual source local is still **`EBP−0x84`**, not original
  `EBP−0x110`; width matching is NOT byte-exactness.
* Native `1FE` and `1FF` both use `FCOMP [00657CF8]`, original
  physical x86 ordinal **47 `TEST AH,5`** followed by ordinal
  **48 `JP`**. The old F666 diagnostic used C++
  `POS>=g_SpeedClampAt00657CF8` which emits **`TEST AH,1; JNE`**,
  materially different for the original floating-point comparison.
  F732 freshly compiled complete giant parents for `>=`, `<`,
  `<=`, `>` and attempted negated control. Only the native-backed
  **strict `<`** form naturally produces *both* correct
  `TEST AH,5; JP` and original complete-width source geometry;
  `<=` has a `JP` but the wrong `AH,0x41` mask. A malformed
  diagnostic negated-expression variant failed compilation, and
  **is not counted as successful source evidence**.

No artificial stack locals, forced machine opcodes, optimizer
profile swap or target EXE modification was needed to recover
these original source semantics and x86 widths.
