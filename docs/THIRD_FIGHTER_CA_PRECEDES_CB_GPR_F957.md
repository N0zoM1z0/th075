# F957 — Native-strict preceding CA source alone does not fix original CB register roles

Pinned Japanese TH075 v1.11 original game fighter
**004AC040** is **82,796 complete callable CODE B /
22,721 x86** and owns **1,126 separately relocated
afterRET DATA B**. The tracked normal VC7.1 original-
shaped whole-parent C++ is still structurally partial:
many native cases and the actual 0x720 frame/saved-this
owner lifetime are not recovered. The original complete
82KB game function remains NONEXACT.

F950's genuine original CA natural source emits
430B/123 x86, **0 wrong native mnemonic and GPR
roles** and only two original six-byte x87
stack-temp instruction widths differ.
The immediately following original CB natural C++
emits 454B/131 x86, **0 wrong native mnemonics**,
but has **79 wrong original GPR roles** beginning
at CB x86 ordinal **5**, plus four genuine
long EBP temp-width differences. The question
was whether changing the **preceding** true
CA source's ordinary C++ value grammar could fix
the next state's allocation, as F953/F955 had
proven for original CC→CD→CE.

## New full father C++ source variants

F957 independently compiled **30 entire original-
shaped, partially reconstructed 82KB VC7.1 parent
sources**, with genuine stage/frame signed-short
reads, comparison ordering, original +0x48
contact and ground float evaluation, actual
source +0x44 and +0x66 signed-facing bullet
arguments, source-lifetime const field views,
and other meaningful real source terms.
One **additional** candidate was rejected
by the actual VC7.1 compiler: declaring the
genuinely written source short field `const`
produces a legitimate C2166 write-to-const
error, so it is **not counted** among
30 successfully compiled candidates.
No fake locals, arbitrary stack padding,
source register forcing, original native
byte grafts or invented command behavior
were introduced.

**Every compiled natural whole-parent source
retained the original CB GPR mismatch count
of 79** (first mismatched register x86
ordinal 5). Changing the source stage
comparison or a true lvalue while
preserving CA's native 123-x86 opcode
geometry did not change CB at all.
Some alternative native-invalid CA
source spellings altered x87
mnemonic order, actual widths and
CA GPR roles for the worse; none
improved following CB.
