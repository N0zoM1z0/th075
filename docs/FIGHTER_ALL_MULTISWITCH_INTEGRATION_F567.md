original after-RET sparse/DWORD DATA are revalidated before a source
build. The C++ for the first eleven real original first-table action

F548/F551/F553/F556/F558/F557/F559/F560/F562 actor families with

## The wide-frame character is a real exception, not false exactness

The original fighter at 00564BE0 stores the actual owner at
**EBP-0x88**, so *all eleven* original action cases use longer
native receiver-pointer loads than the fresh small C++ probe; three
actual branch instructions also require a near JL instead of a short
JL. The entire difference is independently checked at every
single original/candidate instruction:

- **191** original receiver MOV loads with wide EBP-0x88 offsets
  add exactly 3 bytes each: **573 bytes**.
- **3** real near JL branches add 4 bytes each: **12 bytes**.
- Total original minus small-probe case CODE is exactly **585 bytes**.

All other **77/77** new native action-case ranges agree with candidate
case byte lengths. The 00564BE0 **11/11** real native instruction
register/x87/branch grammars also match, but **NOT their literal
byte lengths**. No source padding, manual ASM, fake local array or
byte-for-byte patch is introduced to force false exactness.
